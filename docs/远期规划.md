## Phase 6: Android 前端

### 方案

两个方向，看 Qt6 Desktop 阶段结束后评估：

**方案 A: Qt6 for Android（推荐）**
- 复用 Phase 5 的 C++ 核心库
- Qt6 的 Android 平台支持已经成熟（QSerialPort 在 Android 上通过 `serialport` 插件 + `termux-usb` 或 USB OTG）
- 一套 C++ 代码编译到 Desktop + Android

**方案 B: Flutter 桥接**
- Flutter UI + C++ 核心库通过 `dart:ffi` 调用
- Flutter 的 UI 灵活性优于 Qt6 for Android
- 但多了一层 FFI 调用开销

### 功能

- 触屏优化的大按钮（频率拨号盘风格）
- 基本的频率/模式控制
- 远程连接 Kali 上的 UDP 服务
- **不做频谱**（手机屏幕太小）

## 核心技术债

### 从 Python 到 C++ 的移植

| Python 模块 | C++ Qt6 对应 |
|-----------|-------------|
| `pyserial.Serial` | `QSerialPort` |
| `socket.socket` | `QUdpSocket` |
| `struct.pack` | QDataStream / memcpy |
| `pyaudio` | `QAudioSource` / `QAudioSink` |
| `asyncio` | `QThread` / `QTimer` 事件驱动 |
| `argparse` | `QCommandLineParser` |
| `FastAPI` | `QTcpServer` (可选的 REST) |

### 难点优先级

1. **频谱/瀑布渲染** — 这是最吃性能的部分。Python 的 matplotlib 实时刷新勉强能跑，Qt6 的 QCustomPlot 才能真正流畅
2. **UDP 音频实时性** — 音频 buffer 管理、丢包补偿、延迟控制
3. **Android USB 串口权限** — 需要 `termux-usb` 或 OTG API
